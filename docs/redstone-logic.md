# 红石逻辑模型（本项目权威规则）

本文件是生成器、模拟器与自检脚本共同遵循的红石规则。修改生成逻辑前先读这里。

## 1. 充能等级

### 弱充能（Weakly powered）
- 来源：红石粉的**端点**指向一个实心方块；或强充能方块的水平相邻方块。
- 可以**激活音符盒**。
- **不能**给红石粉供电。
- 可以给**正对它的中继器输入端**供能（中继器能捕获弱充能）。

### 强充能（Strongly powered）
- 来源：中继器输出端正对的一个实心方块；红石块等电源。
- 可以**激活音符盒**。
- 可以给**相邻的任何红石粉**供电：水平四向 + **正上方**（粉在方块上面），**不包括正下方**。
- 会被中继器输入端捕获。
- 会**弱充能水平相邻**的方块；**竖直方向不传递**弱充能。

## 2. 中继器

- 输入端接受：弱充能方块、强充能方块、红石粉、红石块。
- 输出端把正前方的一格实心方块**强充能**。
- `facing` 是「输出侧 → 输入侧」的反向描述：输出方向 = -facing 向量。

## 3. 红石粉的端点与朝向

红石粉有两个可互换的端点（实际最多可呈 X 形四向连接），用来收发信号。它会**自动连接相邻的红石粉**，并据此改变形状：

- 直线形：两端在相对的两个面（左右或前后）。
- L 形：两端在相邻的两个面。
- X 形：四个面都连接。

关键限制：

- **只有端点所指向的面才能弱充能方块。**
- 红石粉**不会凭空拐弯**。一条直线粉的侧面没有端点，因此侧面的音符盒 / 方块**不会**收到任何充能。
- 强充能方块供电给红石粉不受朝向限制（相邻即可），但反向「粉给方块」必须端点正对。
- 端点被相邻红石粉或红石元件占用后，就不能再用来给普通方块弱充能。

常见事故（必须避免）：

```
粉 — 粉 — 粉 → 中继器输出
            ↑
         音符盒（贴在侧面）
```

这条粉是一字形，端点只朝左右，侧面的音符盒收不到电。正确做法是把音符盒放在端点正对的位置，或让中继器直接强充能音符盒 / 用中继器输入端捕获。

## 4. 放置约束（硬性）

- **红石粉、中继器不能悬浮**：正下方必须有实体方块。生成器给每段桥接的粉/中继器补支撑。
- **音符盒正上方不能有任何方块**，包括红石粉、中继器、支撑方块；否则会 mutex / 不发声。
- 因此线路桥的取电点只能二选一：
  - 从**空音符方块**正上方引粉（空音符不是音符盒）；
  - 从**音符盒侧面**引粉（粉与音符盒同一高度、相邻一格），再用中继器接走。
- 内部桥接如果上一段最后一格是音符盒，先补一个空 tick 再取电，绝不在音符盒上方铺粉。

## 5. 本项目的生成约定

- 每条 ABAB 轨道：中继器输出正对音符盒 / 空音符方块 → 强充能；横向移动用红石粉把信号送进**下一级中继器的输入端**。
- 多音符并排：中间音符盒被中继器强充能，作为导体弱充能相邻音符盒。
- 线路桥：
  - 每 2 格 X = 1 个歌曲 tick；1 个中继器 = 2 游戏 tick。
  - 爬升必须借助「中继器 → 实心方块（强充能）→ 正上方红石粉」，不能靠弱充能方块向上传。
  - 爬升段放在捐赠轨道**旁边一列**，避免把桥的方块压在捐赠轨道自己的粉正上方。
  - 桥接失败必须回退成完整轨道或独立启动，不能留下不会响的轨道，也不能跳过副音轨。
  - 桥的水平段从「上一级中继器的输出格」开始铺粉，起点本身就是粉：一段最多 15 格粉，换算成位移上限是 **14 格**。按 15 格位移会铺出 16 格粉，第 16 格强度为 0，末端中继器收不到信号（断链）。
- 可听半径固定为游戏的 **48 格**，不作为可配置项。
- 双轨触发是**动态**的：把每个音量代入音量公式得到目标直线距离，若 `max(距离) - min(距离) > 16`（红石线 15 格 + 音符盒 1 格的物理极限），才拆成主轨 + 外扩副轨；距离差 ≤16 时单轨可以摆渡，不拆。
- 隐形矿车：命令方块链可以放在玩家走廊的左侧 / 右侧 / 上方 / 下方。`summon` 与 `tp` 必须使用**相对坐标 `~`**（结构粘贴到任意世界坐标后仍能工作），偏移量按「命令方块位置 → 走廊」计算：x 对齐音符、y=player_y、**z=base_z（走廊中心）**。不能写死绝对坐标。
- 音量控制排版也支持粒子特效：特效模组只吃「时间 + 坐标」，所以直接从每条选中分组的左侧车道取音符位置，用绝对延迟 `2 × 歌曲 tick + 1` 生成 `/mpe noteblock chain` 数据，与轨道是否被裁剪无关。
- **侧边音符盒的安全侧**：同一 tick 的并排音符盒最多 3 个（中间 + 两侧），但侧边格不能被下一 tick 的横向红石粉扫过。横向粉铺在「下一 tick 中继器所在列的左侧一列」，因此：
  - 轨道向外移动时，侧边音符只能放在**向内**一侧；向内移动时放**向外**一侧；
  - 段尾也必须按整条轨道的下一 tick 判断，不能因为段结束就把 `movement` 当成 0，否则计划与写入的偏移不一致，侧边音符会被换到另一侧后丢掉；
  - 轨道离中轴的最小距离是 **2 格**（`MIN_Z`），保证向内偏移 1 格后仍有 1 格空间，不会与中间音符盒重合；侧边音符到中轴的绝对下限是 1 格，不能越过中轴。
- **副音轨不接外部桥**：主轨与副轨同 Y、同 X 列节奏，外部桥的水平红石粉会与主轨自己的横向粉落在同一列并连成一条（串线）。副音轨改为从 tick 0 铺独立空链并自行启动，时序与发声完整；被裁剪的普通轨道仍然使用线路桥。
- **副音轨整体外置**：副音轨的距离在每一 tick 都要压过主轨当前与下一 tick 的距离再加外扩间距，避免两条轨道的横向移动路径重叠。

## 6. 自检脚本覆盖

- `check_power_paths`：每段红石粉必须能找到合法强电源。
- `check_dust_endpoints`：报告「红石粉侧面对准音符盒」这类不会生效的接触；被中继器输出格直接强充能的音符盒不算。
- 结构测试：每条粉/中继器必须有支撑；音符盒正上方不得有任何方块。
- 链路审计（生成期）`chain_gaps`：每个已生成 tick 必须有中继器和占位音符盒、相邻 tick 的横向粉齐全、桥接入口有粉。
- 通电审计（模拟期）`powered_repeaters`：轨道上存在的每个中继器都必须至少通电一次；「中继器存在但从未通电」就是断链，测试会直接失败。
- 时序测试：生成 → 保存 → 重新加载 → 逐游戏 tick 模拟 → 与 NBS 音符逐 tick 对比。
- 负向测试：故意删掉一段横向红石粉，必须能被模拟缺音、`powered_repeaters` 和 `check_power_paths` 同时检出。
